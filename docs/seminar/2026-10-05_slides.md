## 3. 多クラス分類でのLIMEのやり方

### スライド

- LIMEは出力1本を線形モデルで近似する手法
- 多クラスでは、クラスごとに別々のLIMEを当てる
  - 画像をスーパーピクセルに分け、隠し方を変えた摂動画像を作る
  - 摂動画像ごとにAIの10クラス分の確率を得る
  - クラス0の確率、クラス1の確率、…をそれぞれ線形回帰する
- 結果として、クラスごとのヒートマップが10枚できる

$$
p_k(z)\approx \beta_{k0}+\beta_k^\top z \qquad (k=0,\dots,9)
$$

### 図

摂動画像 → AI → 10本の確率 → 10個の線形モデル → 10枚のヒートマップ

### 話すこと

LIMEは本来、出力1本を説明する手法です。多クラスでは出力が10本あるので、LIMEを10回回すのと同じことをしています。公式の実装では説明するクラスを指定でき、ふつうは予測されたクラス、この例では6だけを見ます。

## 4. 問題点

### スライド

問題1　どのクラスどうしを比べるかを、人が決めている

- 実際には10枚すべては見ず、確率の高い6と0だけを見ることが多い
- 選び方は人任せなので、一緒に動いている9は見落とす
- 確率は高くても、近傍ではほとんど動かないクラスを選んでしまうこともある

問題2　クラス間の関係が見えない

- 確率の和は1なので、6が上がれば別のどこかが下がる
- 知りたいのは「0から6へ確率が移った理由」
- 通常のLIMEでは、6のマップと0のマップを人が見比べて差を読むしかない

### 図

6のヒートマップと0のヒートマップを並べ、間に「人が頭の中で引き算」と書く

### 話すこと

実際に使うときは、10枚のヒートマップをすべて見ることはなく、確率の高い6と0だけを見ると思います。ただ、比べるクラスは人が確率を見て決めたものです。そのため、一緒に動いている9を見落としたり、確率は高いのに近傍ではほとんど動かないクラスを選んだりすることがあります。もう1つの問題はクラス間の関係です。今日の問いは「なぜ0ではなく6か」で、これは6と0の関係についての問いです。ところが通常のLIMEはクラスごとに説明を返すので、関係は人が2枚のマップを見比べて組み立てるしかありません。

## 5. 説明をまとめる2つの方向

|---|---|---|---|---|
| 領域1 | | | | |
| 領域2 | | | | |

  - 既存の手法が多い
- 列（クラス）をまとめる
  - 例　クラス0とクラス6を「0から6への移動」にまとめる
  - **この研究はこちら**

### 図

表の行方向と列方向に矢印を描き、列方向を強調する

### 話すこと

説明を読みやすくするには、この表を小さくすればよいわけです。行をまとめる方向は、画像LIMEのスーパーピクセルがまさにそうで、特徴のグループ化などの手法もあります。この研究は列、つまりクラスの方をまとめます。特徴は元のままなので、どの領域が効いたかという読み方は変わりません。

## 6. 発想

### スライド

- 説明したい画像のまわりだけを見ると、確率が動くのは0・6・9くらい
- 残りの7クラスは、隠し方を変えてもほぼ0のまま
- それなら、確率の動きは少数の方向で表せるはず
  - 方向の例　「0が下がり、6が上がる」

### 図

横軸に摂動画像、縦軸に確率を取った10本の線。0と6の線がシーソーのように動き、9が少し動き、残りはほぼ0で平ら

### 話すこと

説明したい画像のまわりだけを見ると、ほとんどのクラスは動きません。この例で動くのは0と6、それに9が少しです。この動きを少数の方向で表し、方向ごとに説明すれば、量も減り、クラス間の関係も直接読めるはずだ、というのが出発点です。

## 7. 目標とする説明

### スライド

通常のLIME　クラスごとのヒートマップ10枚

この研究　方向（軸）ごとのヒートマップ1〜2枚

| 軸 | 確率の移動 | 出力の動きに占める割合 | ヒートマップ |
|---|---|---|---|
| 軸1 | 0 → 6 | 90% | 左の縦線が6寄り、上の閉じた弧が0寄り |
| 軸2 | 0・6 → 9 | 8% | 9らしく見せる領域 |

（数値は説明のための例）

目標は、**LIMEに劣らない忠実さを保ったまま、解釈しやすさを上げる**こと

### 図

軸1のヒートマップ（赤が6寄り、青が0寄り）と、その上に「0 → 6」のラベル

### 話すこと

目指す出力は、この表のような形です。軸1を見れば「主に0と6で迷っていて、縦線があるから6になった」と読めます。軸ごとに、出力の動きのどれだけを占めるかも出るので、「9の関与は小さい」ことも分かります。条件は、通常のLIMEと比べて、AIの振る舞いを近似する精度をほとんど落とさないことです。

## 8. 手法

### スライド

1. 摂動画像を作り、AIの確率（10個の数）を得る
2. 確率の点の集まりにPCAをかけ、動きの大きい方向（軸）を求める
3. 各摂動画像の確率を、軸の上の1つの数（スコア）に変える
4. スコアを、スーパーピクセルの有無で線形回帰する（ここは通常のLIMEと同じ）
5. 回帰係数をヒートマップにする

| 摂動画像 | 領域A | 領域B | 領域C | 0の確率 | 6の確率 | スコア（6 − 0） |
|---|---|---|---|---|---|---|
| 元画像 | 1 | 1 | 1 | 0.40 | 0.50 | +0.10 |
| Aを隠す | 0 | 1 | 1 | 0.70 | 0.20 | −0.50 |
| Bを隠す | 1 | 0 | 1 | 0.10 | 0.80 | +0.70 |
| Cを隠す | 1 | 1 | 0 | 0.45 | 0.40 | −0.05 |

回帰の結果　スコア ≈ −0.05 ＋ 0.60A − 0.60B ＋ 0.15C

### 図

左に上の表、右に係数を色にしたヒートマップ（A 赤、B 青、C 薄い赤）

### 話すこと

手順の違いは、回帰する目的変数だけです。通常のLIMEは「6の確率」を回帰しますが、この手法は「軸1のスコア」を回帰します。軸1が「6が上がり0が下がる」方向なら、スコアは6寄りか0寄りかを表す1つの数です。表の例では、Aを隠すと0寄りに、Bを隠すと6寄りに動きます。回帰で得られる係数は、Aが正、Bが負です。これをヒートマップにすれば、「Aがあるから6、Bがあるから0の可能性も残った」と1枚で読めます。軸はPCAで近傍の確率の動きから決めるので、どのクラスの対比を見るかを人が選ぶ必要はありません。

## 9. 上位2クラスのLIMEとの違い

### スライド

確率が高い2クラスの差（6 − 0）をLIMEで説明すればよいのでは？

| 状況 | 上位2クラスの差 | この手法 |
|---|---|---|
| 0と6だけが競合 | 同じ結果 | 同じ結果 |
| 0・6・9が競合 | 9を取りこぼす | 複数の軸で表せる |
| どのクラスを比べるか | 確率の高い順に人が決める | 近傍での確率の動きから決まる |

### 話すこと

当然、上位2クラスの差を説明すればよいのでは、という疑問が出ると思います。競合が2クラスだけなら、この手法も同じ結果になります。違いが出るのは、3クラス以上が同時に競合しているときと、確率は高いけれど近傍ではほとんど動かないクラスがあるときです。この手法は確率の動きから軸を決めるので、そうした場合も扱えます。

## 10. 成り立つための仮定

### スライド

仮定1　局所的には、出力が少数の方向にしか動かない（局所的な低次元性）

- 典型的には、近傍で競合するクラスが少ないとき
  - 0と6だけが動くなら、6が上がった分だけ0が下がるので1方向
  - 一般に、動くクラスが m 個なら方向は多くても m − 1 個
- 多くのクラスがまとまって動く場合も、方向は少なくなる

仮定2　局所的には、AIの出力が線形で近似できる

- 通常のLIMEと同じ仮定

### 図

左に「2クラスが動く → 点が直線上に並ぶ」、右に「3クラスが動く → 点が平面上に並ぶ」

### 話すこと

この手法が働くには、2つの仮定が必要です。1つ目は、近傍で出力が動く方向が少ないことです。競合するクラスが少なければ、この仮定は必ず成り立ちます。確率の和が1なので、2クラスだけが動くなら、片方が上がった分だけもう片方が下がり、動く方向は1つです。ただし逆は言えず、多くのクラスがまとまって動く場合にも方向は少なくなります。2つ目は、通常のLIMEと同じ「局所的に線形で近似できる」という仮定です。

## 11. 実験の設計

### スライド

確かめたいこと

1. 近傍で、出力は本当に少数の方向にしか動かないか（仮定1）
2. 少数の軸にまとめても、通常のLIMEと同じくらい忠実か

設定

| 項目 | 内容 |
|---|---|
| データ | 合成データ、10クラスと20クラス、特徴40個 |
| 分類器 | MLP（出力が滑らか）、ランダムフォレスト（出力が階段状） |
| 説明する点 | 予測の迷い（1位と2位の確率差）が大・中・小から各6点、3回の学習で計54点 |
| 近傍 | 説明する点のまわりの正規分布、半径0.15と0.4 |
| 評価 | 学習に使っていない摂動での決定係数 R²（全クラスの確率で計算） |

### 話すこと

実験では2つのことを確かめました。1つ目は仮定1、つまり近傍で出力が少数の方向にしか動かないかです。出力の分散の95%を説明するのに必要な軸の数で測ります。2つ目は、軸を減らしたときに、通常のLIMEと比べてどれだけ忠実さを失うかです。忠実さは、学習に使っていない摂動で、説明のモデルがAIの確率をどれだけ再現できるかで測ります。分類器は、出力が滑らかなMLPと、木の多数決で出力が階段状になるランダムフォレストを比べました。

## 12. 結果1　局所的には少数の方向にしか動かない

### スライド

出力の分散の95%を説明する軸の数（MLP、変動のある近傍の平均）

| | 10クラス | 20クラス |
|---|---|---|
| 半径0.15 | 1.54（動くクラスの数 − 1 は 1.54） | 2.13（同 2.21） |
| 半径0.4 | 2.46（同 2.44） | 3.81（同 3.75） |

- 最大はクラス数 − 1（9または19）だが、MLPでは2〜4軸程度に収まった
- 必要な軸の数は「動くクラスの数 − 1」とほぼ一致した
  - 低次元になる理由は、主に「近傍で競合するクラスが少ない」こと
- ランダムフォレストは動くクラスが多く、20クラスでは平均11〜12軸必要だった

### 図

横軸に「動くクラスの数 − 1」、縦軸に「必要な軸の数」を取った散布図。点が対角線に沿う

### 話すこと

MLPでは、20クラスの分類器でも、近傍の出力はほぼ数軸で表せました。必要な軸の数は、近傍で確率が動くクラスの数から1を引いた値とほぼ同じです。つまり、この合成データでは「競合するクラスが少ない」ことで低次元になっています。一方で、ランダムフォレストは多数決の票が多くのクラスで少しずつ揺れるため、軸を減らせませんでした。

## 13. 結果2　通常のLIMEに劣らないか

### スライド

軸を3本にしたときの R²（通常のLIME → この手法）

| 条件 | 半径0.15 | 半径0.4 |
|---|---|---|
| MLP 10クラス | 0.828 → 0.825 | 0.526 → 0.520 |
| MLP 20クラス | 0.793 → 0.785 | 0.562 → 0.542 |
| ランダムフォレスト 10クラス | 0.735 → 0.678 | 0.743 → 0.676 |
| ランダムフォレスト 20クラス | 0.638 → 0.519 | 0.680 → 0.547 |

- MLPでは、3軸にまとめても失う R² は0.002〜0.02
  - 係数の数は、20クラスなら800個から180個に減る（軸ごとのクラスの重みを含む）
- ランダムフォレストでは失う量が大きい

### 図

横軸に軸の数、縦軸に R²。通常のLIMEの水平線と、この手法の曲線を条件ごとに描く（`result/unified_local_evaluation/fidelity_by_dimension.png`）

### 話すこと

MLPでは、20クラスを3軸にまとめても、通常のLIMEとの差は0.01から0.02程度でした。説明の量は大きく減りますが、忠実さはほとんど変わりません。ランダムフォレストでは、結果1のとおり動く方向が多いので、3軸では足りませんでした。この手法が使えるのは、出力が滑らかな分類器に限られそうです。

## 14. 課題

### スライド

課題1　軸が読めるとは限らない

| 軸の形 | 例 | 読めるか |
|---|---|---|
| 2クラスの対比 | 柴犬 ＋ ／ 秋田犬 − | 読める |
| 1対多 | 柴犬 ＋0.8 ／ 秋田犬 −0.5、三毛猫 −0.3 | 読める |
| 混在 | 柴犬 ＋0.37、三毛猫 ＋0.21 ／ 秋田犬 −0.46 | 読めない |

- 次元が減っても、軸の意味が分からなければ解釈しやすくならない

課題2　通常のLIME自体が忠実でない条件がある

- MLPの半径0.4では、通常のLIMEの R² が0.5台にとどまる
- この手法は通常のLIMEの近似なので、そこは改善できない

### 話すこと

課題は2つあります。1つ目は軸の読みやすさです。PCAの軸は、複数のクラスに重みが分かれることがあります。柴犬が上がって秋田犬と三毛猫が下がる形なら「柴犬の確率は主に秋田犬から来た」と読めますが、柴犬と三毛猫が同じ側に並ぶと意味が取れません。次元を減らすだけでは足りず、減らした後の軸が理解できることも条件になります。2つ目は、通常のLIME自体の忠実さが低い条件があることです。この手法は通常のLIMEを少数の軸で近似するものなので、その限界は引き継ぎます。

## 15. 今後の計画と最終ゴール

### スライド

| 段階 | やること | 確かめること |
|---|---|---|
| 1 | 読める軸の作り方を考える（軸の形を対比や1対多に限る、回転、スパース化） | 忠実さを保ったまま軸が読めるか |
| 2 | 実データで評価する（手書き数字、文字認識など） | 合成データ以外でも仮定が成り立つか |
| 3 | 説明の量をそろえて他の手法と比べる | 同じ量の説明で、より忠実か |
| 4 | 人に説明を見てもらって評価する | 本当に分かりやすくなったか |

最終ゴール

多クラス分類器の予測を「どのクラスからどのクラスへ、どの特徴によって確率が移ったか」という少数の軸で説明し、通常のLIMEより人が理解しやすいことを示す

### 話すこと

次は、軸を読めるようにする方法を考えます。たとえば、軸の形を「2クラスの対比」や「1対多」に限った中で、確率の動きを最もよく表す軸を選ぶ方法です。並行して実データでも評価し、最後は人に説明を見てもらって、本当に分かりやすくなったかを確かめたいと考えています。

## 付録A. 記号

| 記号 | 意味 |
|---|---|
| $K$ | クラス数 |
| $d$ | 特徴（スーパーピクセル）の数 |
| $p(z)\in\mathbb{R}^K$ | 摂動 $z$ に対するAIの確率 |
| $V_q\in\mathbb{R}^{K\times q}$ | PCAで求めた $q$ 本の軸（各列がクラスの重み） |
| $B\in\mathbb{R}^{d\times K}$ | 通常のLIMEの係数行列 |
| 必要な軸の数 | 出力の分散の95%を説明する最小の軸数 |
| 動くクラスの数 | 出力の分散の95%を担う最小のクラス数 |

## 付録B. 通常のLIMEとの関係

全特徴を使う線形回帰（Ridge）は目的変数について線形なので、次が厳密に成り立つ。

$$
\hat p_{\text{この手法}} = \mu + (\hat p_{\text{通常LIME}}-\mu)\,V_qV_q^\top
$$

この手法の予測は、通常のLIMEの予測を $q$ 本の軸に射影したものと一致する。そのため、忠実さで通常のLIMEを上回ることはない。この研究では、通常のLIMEに劣らない忠実さを保ったまま、説明の量を減らし、クラス間の関係を読めるようにすることを目指している。

## 付録C. 想定質問

上位2クラスの差を説明すれば十分では？

- 2クラスだけが競合する近傍では同じ結果になる。実データ4種（手書き数字、文字認識、yeast、ワイン品質）で、軸1本同士を比べた予備実験では、動くクラスが2つ以下の近傍で差はほぼなく、3つ以上の近傍でこの手法の R² が高かった

入力側（特徴）をまとめればよいのでは？

- 入力側をまとめる方法は既にあり、この研究と組み合わせられる。この研究は、まだ扱いの少ないクラス側をまとめる

なぜPCAなのか？

- 出力の動きを最もよく再現する軸が得られるため、まず基準としてPCAを使った。読みやすさのために、軸の形を制限する方法を今後試す

ランダムフォレストでは使えないのか？

- 近傍で多くのクラスの票が少しずつ揺れるため、軸を減らせなかった。通常のLIMEの R² も0.6〜0.7台で、出力が階段状の分類器は線形の近似自体に向かない
